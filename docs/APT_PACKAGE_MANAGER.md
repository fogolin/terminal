## Goals

- `apt install <pkg>` fetches and registers external commands at runtime — no rebuild needed.
- Central public registry served via GitHub Pages lists available packages with source URLs.
- Host websites can preload public packages and inject private/local commands via the config object.
- Installed state persists across sessions via `localStorage`.
- Core bundle stays decoupled from any package code.

---

## High-Level Architecture

```
Host Website
  FirelinTerminal.create({ packages: { preload: [...], local: [...] } })
        │
        ▼
firelin.min.js (core bundle)                     fogolin/firelin-registry
  ├── PackageManager          ← orchestrates     (GitHub Pages)
  │     ├── store.js             everything  ┌───────────────────────────┐
  │     ├── registry.js  ────── fetch ──────►│ registry/v1/index.json    │
  │     ├── loader.js    ────── load  ──────►│ packages/git/1.2.0/index.js│
  │     └── installer.js                     └───────────────────────────┘
  └── AptCommand (apt.js)
        │
        ├── reads ──────────► firelin_registry_cache (localStorage)
        └── writes ─────────► firelin_packages (localStorage)
                                      │
                        on load ──────▼
                              CommandRegistry (Map)
                              ← packages register commands here at runtime
```

**Key invariant:** the core bundle never imports package code. Packages inject themselves into the live command registry via a global callback exposed by the core.

## Registry Repository — `fogolin/firelin-registry`

A dedicated GitHub repository that serves as the public package registry via GitHub Pages.

### Why a separate repo

- Registry lifecycle is independent from terminal releases. Adding a new package shouldn't trigger a terminal version bump.
- Keeps `fogolin/firelin-terminal` CI clean — no package noise in the terminal changelog.
- Lets third parties submit packages via PRs without touching terminal internals.

### Repository File Structure

```
fogolin/firelin-registry/
├── .github/
│   └── workflows/
│       ├── publish.yml        ← builds registry index + deploys to GitHub Pages
│       └── validate.yml       ← PR validation: lint package manifest + script shape
├── packages/
│   ├── git/
│   │   └── 1.2.0/
│   │       ├── index.js       ← the package script (IIFE format)
│   │       └── package.json   ← package manifest (source of truth)
│   └── calc/
│       └── 1.0.0/
│           ├── index.js
│           └── package.json
├── scripts/
│   └── build-registry.js      ← Node script: scans packages/, generates registry JSON
├── registry/
│   └── v1/
│       └── index.json         ← AUTO-GENERATED — do not edit manually
└── README.md
```

`registry/v1/index.json` is committed output generated by CI, not hand-edited.

### Package Manifest (`packages/{name}/{version}/package.json`)

```json
{
	"name": "git",
	"version": "1.2.0",
	"description": "Git-like version control simulation",
	"author": "firelin",
	"license": "MIT",
	"tags": ["dev", "vcs"],
	"commands": ["git"],
	"requires": []
}
```

`src`, `sizeBytes`, and `integrity` are injected by `build-registry.js` at build time — not stored in the manifest.

### GitHub Pages Setup

1. In repo **Settings → Pages**:
   - Source: `GitHub Actions` (not branch deploy).
2. The `publish.yml` workflow deploys the built output to Pages on every push to `main`.
3. Final base URL: `https://fogolin.github.io/firelin-registry/`

### `publish.yml` — Registry Build & Deploy Workflow

```yaml
name: Build and Publish Registry

on:
  push:
    branches:
      - main

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Build registry index
        run: node scripts/build-registry.js
        # Scans packages/, computes SRI hashes, writes registry/v1/index.json

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: .
          # Serves the entire repo root — packages/ and registry/ are both accessible

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deploy.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deploy
        uses: actions/deploy-pages@v4
```

### `validate.yml` — PR Validation Workflow

Runs on every pull request targeting `main`. Blocks merge if validation fails.

```yaml
name: Validate Package PR

on:
  pull_request:
    branches:
      - main
    paths:
      - "packages/**"

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Validate changed packages
        run: node scripts/validate-package.js
        # Checks:
        # - package.json has all required fields
        # - version folder matches package.json version
        # - index.js exists and wraps in IIFE calling window.FirelinTerminal._registerPackage
        # - no built-in command name collisions (git, ls, cd, etc.)
```

### `build-registry.js` — What It Does

```
1. Walk packages/{name}/{version}/ tree.
2. For each version folder:
   a. Read + validate package.json.
   b. Read index.js, compute SHA-384 hash → integrity string.
   c. Compute sizeBytes from index.js file size.
   d. Build package entry: { ...manifest fields, src, integrity, sizeBytes }.
3. For packages with multiple versions, include only the highest semver.
4. Write output to registry/v1/index.json.
```

### Published URLs

| Resource       | URL                                                                      |
| -------------- | ------------------------------------------------------------------------ |
| Registry index | `https://fogolin.github.io/firelin-registry/registry/v1/index.json`      |
| Package script | `https://fogolin.github.io/firelin-registry/packages/git/1.2.0/index.js` |

```json
			"sizeBytes": 4200,
			"src": "https://fogolin.github.io/firelin-registry/packages/git/1.2.0/index.js",
			"integrity": "sha384-abc123...",
			"commands": ["git"],
			"requires": []
		}
	]
}
```

### Config Object Extension

New `packages` key added to the existing config object passed to `FirelinTerminal.create()`.

```javascript
FirelinTerminal.create({
	// all existing fields unchanged
	theme: "phosphor",
	user: "guest",

	// NEW
	packages: {
		registry:
			"https://fogolin.github.io/firelin-registry/registry/v1/index.json", // optional — override default
		preload: ["git", "calc"], // public package names to auto-install on first load
		local: [
			{
				name: "myapp", // must not collide with any public registry name
				description: "Company-specific commands",
				version: "1.0.0",
				src: "/js/myapp-cmd.js", // relative or absolute — host-controlled
				commands: ["myapp", "dashboard"],
			},
		],
	},
});
```

### Installed Package Entry

Stored in `localStorage` under key `firelin_packages` as a JSON object keyed by package name.

```json
{
	"git": {
		"name": "git",
		"version": "1.2.0",
		"src": "https://fogolin.github.io/firelin-registry/packages/git/1.2.0/index.js",
		"integrity": "sha384-abc123...",
		"commands": ["git"],
		"installedAt": "2026-05-03T10:00:00Z",
		"origin": "registry",
		"removed": false
	},
	"myapp": {
		"name": "myapp",
		"version": "1.0.0",
		"src": "/js/myapp-cmd.js",
		"integrity": null,
		"commands": ["myapp", "dashboard"],
		"installedAt": "2026-05-03T10:00:00Z",
		"origin": "local",
		"removed": false
	}
}
```

`removed: true` marks a package soft-deleted by `apt remove` (metadata kept, commands unregistered). `apt purge` deletes the key entirely.

### Registry Cache

Stored in `localStorage` under key `firelin_registry_cache`.

```json
{
	"fetchedAt": "2026-05-03T10:00:00Z",
	"ttlSeconds": 3600,
	"packages": ["...same array as registry JSON..."]
}
```

## Dynamic Loading Strategy

### Why `<script>` injection, not `dynamic import()`

- The core bundle is compiled to **ES5** by Babel + Webpack — there is no native module graph.
- `import()` requires ES modules. Mixing CommonJS (webpack output) with ESM packages causes runtime errors.
- `<script>` injection is universal, works with existing CSP `script-src` headers, and supports SRI natively.

### Registration Protocol

The core exposes a global callback **before** any package scripts are loaded:

```javascript
// set once in src/app.js during init
window.FirelinTerminal._registerPackage = function (packageName, commandDefs) {
	// validate: no built-in command name collisions
	// register each def into the live registry Map
	// resolve the pending install promise for this package
};
```

Every external package wraps itself in an IIFE and calls this callback:

```javascript
// packages/git/1.2.0/index.js
(function (register) {
	register("git", [
		{
			name: "git",
			aliases: ["g"],
			synopsis: "git <subcommand>",
			description: "Git simulation.",
			options: [],
			examples: [],
			execute(args, ctx) {
				/* ... */
			},
		},
	]);
})(window.FirelinTerminal._registerPackage);
```

### Loader Logic (`loader.js`)

```javascript
const loaded = new Set(); // tracks src URLs already injected this session

function loadScript(src, integrity) {
	if (loaded.has(src)) return Promise.resolve();
	return new Promise((resolve, reject) => {
		const s = document.createElement("script");
		s.src = src;
		s.crossOrigin = "anonymous";
		if (integrity) s.integrity = integrity; // SRI for registry packages
		s.onload = () => {
			loaded.add(src);
			resolve();
		};
		s.onerror = () => reject(new Error("Failed to load: " + src));
		document.head.appendChild(s);
	});
}
```

### SRI Policy

| Origin     | SRI hash                                                   | Enforcement                    |
| ---------- | ---------------------------------------------------------- | ------------------------------ |
| `registry` | Required (computed by `build-registry.js` at publish time) | Loader rejects missing hash    |
| `local`    | Not required                                               | Host controls their own server |

## State Management

### localStorage Keys

| Key                      | Contents                          | Cleared by                    |
| ------------------------ | --------------------------------- | ----------------------------- |
| `firelin_packages`       | Map of installed package entries  | `apt purge` (per-package key) |
| `firelin_registry_cache` | Cached registry + fetch timestamp | `apt update` (full overwrite) |

These join the existing keys `firelin_vfs`, `firelin_history`, `firelin_theme`.

### Store Interface (`store.js`)

```javascript
const Store = {
  getAll()              // → { [name]: PackageEntry }
  get(name)             // → PackageEntry | null
  set(name, entry)      // → void
  markRemoved(name)     // → void  (sets removed: true — soft delete)
  purge(name)           // → void  (deletes key entirely)
  isInstalled(name)     // → boolean (exists and removed: false)

  getRegistryCache()    // → { fetchedAt, ttlSeconds, packages } | null
  setRegistryCache(d)   // → void
  isCacheStale()        // → boolean
  clearRegistryCache()  // → void
};
```

### Command Operations Matrix

| Command             | Registry Cache      | Store                       | Command Registry Map                |
| ------------------- | ------------------- | --------------------------- | ----------------------------------- |
| `apt update`        | Refetch + overwrite | No change                   | No change                           |
| `apt upgrade`       | Read                | Update version + src fields | Re-load script for each changed pkg |
| `apt install <pkg>` | Read → resolve URL  | `set()` with new entry      | Register commands                   |
| `apt remove <pkg>`  | No change           | `markRemoved()`             | Delete commands from Map            |
| `apt purge <pkg>`   | No change           | `purge()`                   | Delete commands from Map            |

### remove vs purge

- **`apt remove`** — unregisters commands from the live Map. Keeps package metadata in `localStorage`. Fast reinstall path; `apt upgrade` can still track the package.
- **`apt purge`** — unregisters commands and deletes the `localStorage` entry completely. Package treated as never installed.

## Boot Sequence

Called from `src/app.js` inside `FirelinTerminal.create(config)`, before the terminal becomes interactive.

```
1. Expose window.FirelinTerminal._registerPackage callback.

2. Load firelin_packages from localStorage.

3. For each stored entry where removed === false:
     → loadScript(entry.src, entry.integrity)
     → restores all previously-installed commands without hitting the network.

4. For each entry in config.packages.local:
     → treat as origin: "local"
     → loadScript(entry.src, null)  // no SRI
     → store entry if not already stored.

5. For each name in config.packages.preload:
     a. Already installed (removed === false)? → skip.
     b. Else: fetch registry (use cache if fresh), find entry, loadScript + install.

6. Register apt command in core command registry.
```

A returning visitor skips steps 4–5 for already-installed packages. First visit only installs `preload` list.

## Command Interface

### `apt update`

```
apt update
```

Fetches registry JSON, overwrites `firelin_registry_cache`. Reports package count.

```
Fetching package list from https://fogolin.github.io/firelin-registry/registry/v1/index.json...
OK. 42 packages available.
```

### `apt install <pkg>`

```
apt install git
apt install git calc nano-plus
```

Resolves package from cache (auto-fetches registry if cache is stale). Loads script, registers commands, writes to store.

```
Reading package lists... Done
Installing git (1.2.0)...
1 new command registered: git
Done.
```

### `apt remove <pkg>`

```
apt remove git
```

Unregisters commands. Keeps metadata.

```
Removing git...
Command 'git' unregistered. Run 'apt install git' to reinstall.
```

### `apt purge <pkg>`

```
apt purge git
```

Unregisters commands. Deletes all stored data for package.

```
Purging git...
All data for package 'git' removed.
```

### `apt upgrade`

```
apt upgrade
```

Compares installed versions against registry. Prompts per package, then re-loads updated scripts.

```
Reading package lists... Done
2 packages can be upgraded: git (1.2.0 → 1.3.0), calc (2.0.1 → 2.1.0)
Upgrade all? [Y/n]
```

### `apt list`

```
apt list           # all available (from registry cache)
apt list --installed
```

## Implementation Steps

Work in this order. Registry repo setup (Step 0) can run in parallel with terminal work (Steps 1–8).

### Step 0 — Create `fogolin/firelin-registry` repo

- Create new public GitHub repository `fogolin/firelin-registry`.
- Add folder structure: `packages/`, `scripts/`, `registry/v1/`.
- Write `scripts/build-registry.js` — walks `packages/`, computes SRI hashes, writes `registry/v1/index.json`.
- Write `scripts/validate-package.js` — checks manifest fields, IIFE shape, command name collisions.
- Add `package.json` with `build` and `validate` scripts.
- Add `.github/workflows/publish.yml` — build + deploy to GitHub Pages on push to `main`.
- Add `.github/workflows/validate.yml` — validate on PRs touching `packages/`.
- Enable GitHub Pages in repo Settings → Pages → Source: GitHub Actions.
- Add a seed package (`git` or `calc`) to verify the full pipeline end-to-end.
- Confirm `https://fogolin.github.io/firelin-registry/registry/v1/index.json` is reachable.

### Step 1 — `store.js` (terminal repo)

- Implement `Store` object with all methods listed above.
- All localStorage reads/writes wrapped in try/catch.
- No dependencies on other new modules.

### Step 2 — `registry.js`

- Implement `fetchRegistry(url)` — fetches JSON, validates shape, returns packages array.
- Implement `getRegistry(url)` — returns cache if fresh, else calls `fetchRegistry` + updates cache via `Store`.
- Default URL constant: `https://fogolin.github.io/firelin-registry/registry/v1/index.json`.
- Depends on: `store.js`

### Step 3 — `loader.js`

- Implement `loadScript(src, integrity)` with `loaded` Set dedup.
- SRI enforcement: if `origin === 'registry'` and no integrity hash, reject with error.
- Returns `Promise<void>`.
- No dependencies on other new modules.

### Step 4 — `installer.js`

- Implement `install(pkgEntry, commandRegistry)` — calls `loader.loadScript`, then writes to store.
- Implement `remove(name, commandRegistry)` and `purge(name, commandRegistry)`.
- Implement `upgrade(commandRegistry)` — diff versions, reload scripts.
- Depends on: `store.js`, `loader.js`

### Step 5 — `index.js` (PackageManager public API)

- Export `boot(packagesConfig, commandRegistry)` — runs boot sequence from §Boot Sequence.
- Export `install`, `remove`, `purge`, `update`, `upgrade`, `list` — called by `apt.js`.
- Exposes `window.FirelinTerminal._registerPackage` callback.
- Depends on: all of steps 1–4.

### Step 6 — `apt.js` (command module)

- Thin command module following the standard command interface (see `COMMAND_MODULE.md`).
- Parses first positional arg as subcommand (`update`, `install`, `remove`, `purge`, `upgrade`, `list`).
- Delegates to `PackageManager`.
- Depends on: `packages/index.js`.

### Step 7 — Wire into core

- `src/shell/commands/index.js` — import and register `apt`.
- `src/app.js` — call `PackageManager.boot(config.packages, registry)` during init.
- Expose `_registerPackage` on `window.FirelinTerminal` before boot runs.

### Step 8 — Package authoring guide

- Add `docs/PACKAGE_AUTHORING.md` with the IIFE contract, registration API, and a minimal example package.
